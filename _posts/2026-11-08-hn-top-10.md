### 2. [Petered (what happens after the Peter Principle)](https://aworkinglibrary.com/writing/petered)
⭐ 21 💬 10 👤 adrianhoward
[🔗 Discuss on HN](https://news.ycombinator.com/item?id=50412152)

The article argues that the Peter Principle is not a stable endpoint: people promoted beyond their competence face career pressure that can drive them to perform risky or unethical tasks, sabotage others, or create vacancies to preserve their positions. This dynamic turns such leaders into real imposters who rely on obscurity and busyness to mask their inability to fulfill their roles. It also suggests that imposter syndrome can shift blame onto individuals while obscuring the actual imposters and systemic structures that create them.

### 4. [JIT bitmap text rendering for microcontrollers](https://linebender.org/blog/jit-bitmap-text/)
⭐ 7 💬 0 👤 dmit
[🔗 Discuss on HN](https://news.ycombinator.com/item?id=50412072)

The article describes a high-performance bitmap text rendering technique for microcontrollers such as the RP2350, using just-in-time generated code to draw strings directly while racing the video beam. It avoids large framebuffers and fixed character cells, enabling proportional spacing and kerning with low latency. The approach is implemented in a custom assembly-oriented language and integrated into a display-list renderer.

### 7. [Agent memory needs its OpenTelemetry moment](https://www.lorekit.io/blog/open-agent-memory-format)
⭐ 62 💬 60 👤 mthines
[🔗 Discuss on HN](https://news.ycombinator.com/item?id=50411467)

Agent memory is fragmented across incompatible formats such as repository instruction files, agent-managed memory files, and MCP-based memory servers, so lessons learned by one tool cannot be used by another. The article argues the field needs a shared standard, similar to OpenTelemetry, covering a common data model, semantic conventions, protocol, and reference implementations. With formats still young and neutral standards bodies emerging, now is the time for the community to agree on an open agent memory format.

### 8. [Claude Code's "Don't Ask Again" exposes passwords in 1,122 public GitHub files](https://apiiro.com/blog/coding-agents-leaking-secrets-github-dont-ask-again)
⭐ 434 💬 292 👤 shmulc
[🔗 Discuss on HN](https://news.ycombinator.com/item?id=50407882)

Researchers found that Claude Code's "don't ask again" permission feature can store full shell commands, including passwords, API keys, and connection strings, in local settings files that developers sometimes commit to public GitHub repositories. The study identified 1,122 public copies of Claude Code settings files containing real secrets, with thousands of exposed credentials across nearly 2,000 repositories and 63 organizations. The issue arises because the saved permission rule includes the secret-bearing command, and the file is not reliably protected from being committed, so affected teams should search their repos and rotate any exposed credentials.
